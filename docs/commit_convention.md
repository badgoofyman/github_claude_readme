# Commit Convention

## 기본 형식

```
<type>(<scope>): <subject>

<body>

<footer>
```

---

## Type

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `style` | 코드 포맷팅, 세미콜론 누락 등 (로직 변경 없음) |
| `refactor` | 코드 리팩토링 (기능 변경 없음) |
| `test` | 테스트 코드 추가 또는 수정 |
| `chore` | 빌드 설정, 패키지 업데이트 등 기타 작업 |

---

## 규칙

- `Type`은 앞뒤로 대문자 '[]'를 사용해서 감싸야 한다.
- `subject`는 50자 이내로 작성합니다.
- `subject`는 마침표를 붙이지 않습니다.
- `subject`는 명령형으로 작성합니다. (예: "변경합니다" → "변경")
- `body`는 선택 사항이며, 변경 이유와 내용을 설명합니다.
- `footer`는 선택 사항이며, 관련 이슈 번호를 참조합니다. (예: `Closes #123`)

---

## 예시

```
[feat](auth): 소셜 로그인 기능 추가

구글 OAuth 2.0을 이용한 소셜 로그인 기능을 구현합니다.

Closes #42
```

```
[fix](api): 사용자 목록 조회 시 빈 배열 반환 오류 수정
```

```
[docs]: commit convention 초안 작성
```
